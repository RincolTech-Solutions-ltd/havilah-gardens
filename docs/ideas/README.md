# From idea to website

Esther puts ideas in the Havilah Group WhatsApp chat or sends them to Hillary: a photo of a planter, a reel she
likes, a product name, a price, a layout. Nothing should get lost between the chat and the site.

## The flow

1. **Capture.** Every idea becomes a GitHub issue using the "Idea" template, labelled `idea`. One idea per issue.
   Photos go in the issue only if they are ours or free to use; for anyone else's reel or photo, just write what we
   liked about it.
2. **Decide.** Esther says yes, later or no. A "yes" gets labelled `accepted` and is split into tasks; "later" stays
   open with the label `later`; "no" is closed with a one-line reason.
3. **Build.** A pull request links the issue, and the issue closes when the change is live.
4. **Show.** Esther sees each change on the preview site before it goes live.

## What never goes in an issue

This repository is public (ADR-002). Buying prices, costs, margins, supplier details, phone numbers and addresses stay
in the private chat. The issue can say "price to be agreed".
